01 / BACKGROUND

建设背景：校园安全治理的四道难题

看得见，看不懂

  • 摄像头数量多，依赖人工盯屏
  • 夜间与楼道盲区事件发现滞后
  • 事后翻查录像耗时耗力

霸凌隐蔽，取证困难

  • 围堵、推搡、言语威胁持续时间短
  • 学生不敢主动报告
  • 缺乏客观行为证据链

发现与处置割裂

  • 发现、上报、调度分散在不同系统
  • 响应慢、责任边界不清
  • 处置过程无完整记录

数据沉睡，难以复盘

  • 事件停留在纸质记录或聊天工具
  • 无法做区域与时段趋势分析
  • 难以支撑德育决策
核心命题

把监控从「只能看」升级为「能识别、能告警、能处置、能复盘」，
让校园安全治理从「事后追责」前移到「事中干预」。

05 / VISION

核心能力一：计算机视觉行为识别

输入：校园监控视频经姿态估计得到 COCO-17 关键点序列，算法层做纯几何判定，无需 GPU 即可运行。

摔倒检测

  • 躯干倾角 = 肩中点 → 髋中点与竖直方向夹角
  • θ > 65° 判定摔倒
  • 角度越接近 90°，置信度越高
fall_angle = 65°

攻击检测

  • 逐帧计算双手腕位移之和
  • 滑窗内计算位移 Z-Score
  • Z > 3.0 判定为突发攻击
attack_z = 3.0

围堵检测

  • 任意两人肩中点距离与平均肩宽比较
  • 距离 < 3.5 × 肩宽判定围堵
  • 人数越多、间距越近置信度越高
surround_ratio = 3.5

多信号叠加：攻击 + 围堵（或摔倒）→ 自动判定「疑似校园霸凌」并升级红色预警；单信号只按基础级别告警，避免误报升级。

06 / ALERTING

核心能力二：分级预警与多信号升级

信号组合预警类型级别自动动作
仅攻击疑似暴力攻击红色语音震慑 + 领导通知
仅摔倒人员摔倒橙色通知安保与班主任
仅围堵多人围堵黄色推送值班员核实
攻击 + 摔倒疑似校园霸凌红色震慑 + 安保调度
攻击 + 围堵疑似校园霸凌红色震慑 + 安保调度
摔倒 + 围堵多信号冲突红色安保到场 + 通知
三类同时出现疑似校园霸凌红色启动干预预案

去重与降噪

  • 去重键：摄像头 + 类型
  • 窗口 60 秒，可配置
  • 避免同一事件刷屏

自动震慑

  • 红色预警自动排队语音干预
  • 固定话术：立即停止危险行为
  • 同步推送安保与班主任
级别含义：红（紧急，可能正在发生霸凌 / 暴力）· 橙（高风险，立即核实）· 黄（需关注）· 蓝（提示观察）
