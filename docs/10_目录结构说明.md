## 2. 分层职责

| 层 | 目录 | 职责 | 变更频率 |
| --- | --- | --- | --- |
| 服务层 | `server/`、`seat_monitor/` | HTTP 服务与业务闭环 | 中 |
| 算法层 | `ai/` | 纯算法判定，零 I/O | 低 |
| 业务运行时 | `campus_ai/` | 可复用 AI 业务能力 | 中 |
| 演示层 | `demo/`、`web/`、`seat_monitor/web/`、`ppt/` | 演示与展示 | 中 |
| 配置层 | `config/`、`seat_monitor/settings.json` | 全部外置配置 | 高 |
| 数据层 | `data/`、`archive/` | 运行时产物，不纳入版本控制 | — |
| 资产层 | `audio_assets/` | 语音样本与转写 | 低 |
| 文档层 | `docs/` | 标准化文档；`reference/` 为只读历史资料 | 低 |
| 测试层 | `tests/` | 单元与集成测试 | 中 |

## 3. 命名与放置规范

| 规范 | 说明 |
| --- | --- |
| 目录命名 | 小写蛇形（`seat_monitor`）；文档按 `NN_名称.md` 编号排序 |
| 模块内聚 | 模块自包含：配置、数据、前端、权重均放在所属模块目录内 |
| 配置外置 | 代码不写死路径；相对路径由 `resolve_path` 统一解析 |
| 运行时产物 | 一律落在 `data/`、`archive/`、`seat_monitor/snapshots/`、`seat_monitor/events.json`，全部 gitignore |
| 测试对应 | `tests/` 与被测模块同名：`test_<模块或能力>.py` |
| 参考资料 | 历史/外部资料只读归档在 `docs/reference/`，不与现行文档混放 |
