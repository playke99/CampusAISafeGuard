## 1. 搭建规范提取

| 维度 | 规范来源 | 要求 |
| --- | --- | --- |
| 库文件 | `config/app.json → app.db_path` | `data/campus_security.db`，WAL 模式 |
| 表结构 | `schema.sql` | 10 张业务表：users/sessions/alerts/interventions/events/work_orders/violations/push_records/devices/audit_logs |
| 字段约束 | `schema.sql` | 主键自增、业务编号 UNIQUE、必填字段 NOT NULL + 默认值、时间统一 Unix 秒（REAL） |
| 索引规则 | `schema.sql` + 评估报告 5.4 | 高频过滤字段（status/severity/time）+ 关联追溯字段（event_id/alert_id）必须有索引 |
| 关联关系 | 设计文档 | `alerts.event_id` ↔ `events` ↔ 工单/违规/推送；轻量方案采用应用层一致性，不声明 FOREIGN KEY |
| 种子数据 | `server/core/db.py` | 5 个预置账号（PBKDF2 哈希）+ 11 台设备 |
| 验收标准 | 评估报告 | 完整性 ok、结构核对零偏差、性能达标、备份可恢复 |

## 2. 执行步骤与日志

执行命令：

```bash
python scripts/db_setup.py --reset --demo-data
```

| 步骤 | 操作 | 结果（摘自 logs/db_setup_20261112_171434.log） |
| --- | --- | --- |
| STEP 1 | 实例初始化：删除旧库文件（含 -wal/-shm），创建 data/ 目录 | `目标库 ...\data\campus_security.db` |
| STEP 2 | 库名配置确认：解析 `app.db_path` | `app.db_path=data/campus_security.db` |
| STEP 3 | 表结构创建：`init_db` 执行 schema.sql | `schema.sql 执行完成（含种子数据）` |
| STEP 4 | 结构产物核验 | `表 10 张`；`索引 11 个`（含 idx_alerts_event） |
| STEP 5 | 外键策略确认 | `PRAGMA foreign_keys=1`；应用层一致性（设计决策） |

## 4. 可重复搭建说明

| 场景 | 命令 |
| --- | --- |
| 保留数据增量搭建 | `python scripts/db_setup.py`（schema 幂等，IF NOT EXISTS） |
| 重置重建 | `python scripts/db_setup.py --reset` |
| 含演示数据 | 追加 `--demo-data` |
| 指定库路径 | 追加 `--db 路径` |

- `schema.sql` 全部使用 `CREATE TABLE/INDEX IF NOT EXISTS`，重复执行安全；
- 种子数据采用「不存在才插入」策略（`INSERT OR IGNORE` / 存在性检查），幂等；
- 演示数据编号固定（`ALM-DEMO-*`），重复导入自动去重。
