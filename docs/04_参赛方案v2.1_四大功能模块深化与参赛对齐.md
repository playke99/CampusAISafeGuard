## 2. 模块一：本地 Agent 智能体

> 工程实现：`campus_ai/agent_service/`（service / parsers / llm_client / report_builder），配置 `config/campus_config.json` 的 `agent` 节点。

### 2.1 语音、视频数据采集标准

#### 2.1.1 音频采集标准

| 参数 | 标准值 | 说明 |
| --- | --- | --- |
| 采样率 | 16000 Hz | 与 SenseVoice / 能量 VAD 输入对齐 |
| 位深 / 声道 | 16 bit PCM / 单声道 | 多声道先混音降采 |
| 容器格式 | WAV（无压缩 PCM） | 避免有损编码影响转写 |
| 单段时长 | VAD 切分后 0.5–30 s | 超长段强制切分，防止单次研判超时 |
| 端点检测 | 帧长 25 ms，静音端点 300 ms | 现行 `ai/audio/vad.py` 参数 |
| 响度归一 | 峰值归一化至 -3 dBFS | 消除设备增益差异 |

#### 2.1.2 视频采集标准（继承获奖方案"8 秒证据"规范）

| 参数 | 标准值 | 说明 |
| --- | --- | --- |
| 分辨率 / 帧率 | 1920×1080 @ 15 fps | 边缘端推理输入可降采至 960 宽 |
| 编码 | H.264（关键帧间隔 ≤ 2s） | 保证证据片段可快速截取 |
| 证据窗口 | 触发点前 5 s + 触发后 3 s，共 8 s | 获奖方案"行车记录仪式取证"规范 |
| 关键帧抽取 | 每秒 1 帧 JPEG，质量 80 | 供多模态大模型视觉输入 |
| 姿态数据 | COCO-17 关键点，随帧保存 | 与视频证据同时间轴，供报告引用 |

#### 2.1.3 格式转换规则

```text
原始音频（任意编码）→ ffmpeg 转码 → 16k/16bit/mono WAV → 响度归一 → VAD 切分
原始视频（RTSP/文件）→ 解码 → 降采 960 宽（推理用）/ 保留 1080p（证据用）
                    → 证据窗口截取（前5s+后3s）→ H.264 片段 + 每秒1帧 JPEG
```

规则约束：

1. 推理用帧与证据用帧**同坐标系**：检测框、姿态骨架、快照均基于降采帧标注，证据片段按缩放系数回投；
2. 转换失败（编码损坏、时长不足 8s）不阻断流程：按实际可用窗口生成证据，并在报告 `evidence_note` 字段标注；
3. 全部转换产物落盘前统一命名：`{event_id}_{seq}.{ext}`，保证"一事一档"可检索。

### 2.2 结构化报告的生成逻辑

#### 2.2.1 生成流水线（现行实现，与获奖方案一致）

```text
MediaBundle（音频路径 + 视频路径 + 元数据）
  → parse_bundle：ASR 转写（SenseVoice/模拟降级）+ 视频元数据解析
  → LLM 深判：Qwen2.5-VL（本地 Ollama，use_ollama 开关）/ 规则降级
  → render_report：结构化 JSON + Markdown 双产物
  → 生成 STRUCTURED_REPORT 事件 → 按级别路由推送 → 总线归档
```

#### 2.2.2 报告 JSON 契约

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `summary` | string | 一句话事件概述（≤60 字） |
| `severity` | enum | red / orange / yellow / blue，与全局分级一致 |
| `event_type` | string | bullying / attack / fall / surround / danger_speech 等 |
| `timeline` | array | 关键时点序列（秒级），引用证据窗口时间轴 |
| `evidence` | object | 命中危险词、姿态信号、置信度、证据文件引用 |
| `suggestion` | array | 分级处置建议（到场核实 / 通知对象 / 取证要点） |
| `transcript` | string | 语音转写全文（脱敏后入档） |

降级策略：Ollama 不可达或超时（`agent.timeout=30s`）时静默切换规则化研判，报告结构不变，`evidence_note` 标注"规则生成"，保证评审演示与生产运行都不中断。

### 2.3 推送渠道规范

| 渠道 | 承载 | 适用级别 | 时效要求 |
| --- | --- | --- | --- |
| 站内推送 | `push_records` 表 + 看板预警中心 | 全部 | 事件生成后 ≤ 1 s 可查 |
| 实时大屏 | WebSocket / 轮询推送态势看板 | 红 / 橙 | ≤ 3 s 上屏 |
| 语音震慑 | 本地音频资产播放（红/橙/黄话术） | 红（自动）/ 橙黄（对讲触发） | 红色告警后 ≤ 2 s 播放 |
| 外部 Webhook | `push.endpoint` + Token + 重试 3 次 | 红 / 橙 | 端到端 ≤ 5 s |
| 移动端（规划） | 小程序订阅消息 | 红 | 分钟级，二期接入 |

推送路由矩阵（现行 `agent.route` / `ALERT_TARGETS`）：

| 级别 | 推送目标 |
| --- | --- |
| 红 | 安保负责人、值班领导、班主任 |
| 橙 | 安保值班员、班主任 |
| 黄 | 安保值班员 |
| 蓝 | 记录归档（学工处/图书管理员按事件类型定向） |

### 2.4 部署架构

```text
单机部署（本期交付）
  FastAPI(8100) ─┬─ campus_ai AgentService（进程内）
                 ├─ Ollama Qwen2.5-VL（localhost:11434，可选增强）
                 └─ SQLite(WAL) + archive/ JSONL
容器化（评审演示推荐，对齐获奖方案 Docker 叙事）
  docker-compose：app / ollama 两服务，镜像标签化，3 分钟拉起
横向扩展（规划）
  采集端 → Kafka → Flink 实时复核 → 告警服务 → WebSocket 大屏
                                    └→ Spark 批量分析（高危规律挖掘）
```

### 2.5 性能指标要求

| 指标 | 目标值 | 测量口径 |
| --- | --- | --- |
| 音频转写时延 | ≤ 2 s / 10s 音频 | VAD 切分完成到转写返回 |
| 报告生成时延（LLM） | ≤ 30 s | Ollama 超时阈值即 SLA 上限 |
| 报告生成时延（规则降级） | ≤ 200 ms | 纯规则研判 |
| 事件到推送可查 | ≤ 1 s | 事件写入到 `/api/v1/events` 可见 |
| 研判可用性 | 100%（含降级） | LLM 故障不阻断事件生成 |
| 吞吐 | ≥ 500 条事件/秒（告警引擎） | 对齐获奖方案 Flink 实测口径，单机为内存判定无 I/O 瓶颈 |

## 3. 模块二：对讲功能设备（危险词干预）

> 工程实现：`campus_ai/intercom_service/`（service / audio_io / danger_words），词库 `config/danger_words.json`。

### 3.1 设备硬件参数标准（老师指导意见落实）

| 部件 | 参数 | 标准 |
| --- | --- | --- |
| 收音 | 麦克风类型 | 全向驻极体 / MEMS 麦克风阵列（≥2 麦） |
| | 拾音半径 | 5–8 m（走廊、自习区覆盖） |
| | 灵敏度 | -38 dB ± 3 dB |
| | 信噪比 | ≥ 60 dB |
| | 采样输出 | 16 kHz / 16 bit，与 2.1.1 采集标准一致 |
| | 前端处理 | AEC 回声消除 + 降噪（播放制止话术时防自激） |
| 播放 | 扬声器功率 | 3–5 W |
| | 声压级 | ≥ 85 dB @ 1 m（嘈杂走廊可闻） |
| | 频率响应 | 300 Hz–8 kHz（语音清晰度优先） |
| 整机 | 网络 | PoE / Wi-Fi，断网本地缓存事件 |
| | 环境 | -10 ℃–50 ℃，室内半隐蔽安装（防破坏） |

### 3.2 危险词库构建规则

#### 3.2.1 三级分类标准（与获奖方案词表完全一致）

| 级别 | 语义类别 | 词表示例（现行词库） | 处置 |
| --- | --- | --- | --- |
| 红 | 紧急求救、生命安全 | 救命、报警、110、帮帮我、杀人、着火了 | 立即告警 + 语音震慑 + 安保负责人/值班领导推送 |
| 橙 | 正在发生的暴力/胁迫 | 别打我、放过我、我错了、打死你、弄死你、找死、有种别跑 | 告警 + 值班员到场 + 班主任推送 |
| 黄 | 辱骂、贬低、挑衅 | 废物、垃圾、傻X、滚、蠢货、丑八怪 | 记录 + 班主任关注 |

#### 3.2.2 词库治理流程

1. **入库评审**：新词须标注级别、语义类别、典型语境，由德育处 + 保卫处双人评审；
2. **变体扩展**：同音/谐音（如"就命"）、方言高频词、网络缩写在评审后入库，匹配前文本归一化（去空白、统一大小写、全半角转换）；
3. **热更新**：`POST /api/v1/danger-words` 在线更新，立即生效，变更写入审计日志；
4. **定期复审**：每学期末结合命中日志复审一次，移除零命中干扰词，下调误报高频词级别。

### 3.3 实时语音信息提取流程

```text
麦克风阵列 PCM 流
 → 能量 VAD（25ms 帧 / 300ms 静音端点）切出语音段
 → ASR 实时转写（生产：SenseVoice；演示：模拟转写降级）
 → 文本归一化
 → 危险词分级匹配（红→橙→黄 顺序，取最高级别）
 → 命中：生成 ALERT 事件 + 推送 + 播放对应级别制止话术
 → 未命中：丢弃，不产生事件（防误报设计）
```

### 3.4 危险内容比对分析算法

| 环节 | 算法 | 说明 |
| --- | --- | --- |
| 归一化 | 去空白、大小写/全半角统一 | 消除转写格式噪声 |
| 匹配 | 红→橙→黄 顺序子串匹配，取最高命中级别 | 现行实现，O(n·m) 对词库规模足够 |
| 演进 | AC 自动机多模匹配（词库 >500 条时启用） | 单次扫描命中全部模式，复杂度与文本长度线性 |
| 容错（规划） | 拼音相似度比对，覆盖同音变体 | 降低方言/口齿不清漏报 |
| 上下文增强（规划） | 连续两段语音命中升级一级 | 单句误听不误报，持续冲突必升级 |

### 3.5 告警触发判定、推送路径与响应时效

| 项 | 规范 |
| --- | --- |
| 触发条件 | 任一危险词命中即触发；命中级别 = 词表最高级别 |
| 去抖 | 同设备同级别 60 s 内不重复告警（复用全局 `dedupe_seconds` 口径） |
| 推送路径 | 红 → 安保负责人 + 值班领导；橙 → 安保值班员 + 班主任；黄 → 安保值班员 |
| 制止话术 | 按级别播放 `audio_assets/deter_{red,orange,yellow}.wav`，播放动作生成 DETERRENCE 事件留痕 |
| 响应时效 | 收音结束 → 告警生成 ≤ 3 s；红色告警 → 制止话术播放 ≤ 2 s；告警 → 看板可见 ≤ 3 s |
| 功能优化点（老师指导） | ① 播放话术时暂停收音 3 s 防自激误触发；② 断网本地缓存事件，恢复后补推；③ 设备心跳纳入设备管理页，离线 5 分钟告警 |

## 4. 模块三：图书馆霸座监测

> 工程实现：`seat_monitor/`（独立服务，端口 8200）+ 主系统 `/api/seat_event` 工单闭环；实现细节见 docs/02_占座监测专项方案.md，本章补充场景化运营规范。

### 4.1 物品识别精度要求

| 项 | 指标 | 说明 |
| --- | --- | --- |
| 检测类别 | 背包、手提包、书本、水杯、笔记本电脑等 7 类（COCO） | 训练集外物品（衣物等）由背景建模静态遗留物兜底 |
| 精度目标 | mAP@0.5 ≥ 0.85；单类召回 ≥ 0.80 | 自习区固定机位、俯视角度下实测口径 |
| 命中判定 | 物品框底边中心落入座位 ROI（归一化多边形） | 坐标系唯一，ROI 与分辨率解耦 |
| 辅助证据 | ROI 前景占比 ≥ 0.10 且 30 s 窗口波动 ≤ 0.05 → 判"静态遗留物" | 仅补充"物"证据，永不参与"人"判定 |
| 人在座判定 | 上半身关键点 / 人框上半段落点命中 ROI | 人静坐不误判为空位 |

### 4.2 位置占用时间统计规则

| 参数 | 默认值 | 统计规则 |
| --- | --- | --- |
| 检测频率 | 1 次/秒 | 状态机逐次推进，时间戳以检测时刻为准 |
| 离开确认 | 连续 3 次未检出人 | 单帧漏检不计离开 |
| 暂离宽限期 | 180 s | 取书、上厕所不计入占用计时 |
| 计时起点 | 宽限期结束且座位仍有遗留物 | TIMING 状态开始累计缺席时长 |
| 计时终点 | 人回座（自动关单）或物品被拿走（复位 FREE） | — |
| 统计粒度 | 按座位独立计时，支持按座位覆盖阈值 | `seat_thresholds: {"A01": 15}` |

### 4.3 霸座判定阈值

| 情形 | 判定 | 级别 |
| --- | --- | --- |
| 首次超时，缺席 25–30 分钟 | 疑似占座，生成事件 + 工单 | 黄 |
| 超时 > 30 分钟 或 当日重复触发（repeat_count ≥ 2） | 恶意占座嫌疑，摘要标注"第 N 次" | 橙 |
| 一人多座（邻座 ROI 中心距 < 1.5 倍本座尺度且邻座有人） | 事件标记 `multi_seat`，升级提醒 | 橙 |
| 预约时段内人不在座 | 事件附预约卡号尾号，供管理员核对 | 随主级别 |

全局阈值 25 分钟，期末周等高峰可整体下调至 15–20 分钟（`POST /api/settings` 热更新）。

### 4.4 图书管理员操作处理流程

```text
接收工单（看板"工单闭环"页 / 监测端告警列表，待处理置顶）
 → 到场核实（依据事件附带的实时快照与座位号）
 → 三选一处置：
    · 贴提示条（首次、情节轻）— 事件标记已提示
    · 清座（超时严重/多次）— 物品移交服务台登记，事件标记已清座
    · 误报（实际有人/物品已取）— 标记误报，样本回流优化阈值
 → 工单闭环（写审计日志：操作人、动作、时间、座位）
特殊情况：人回座 → 系统自动关单"已自动关闭(人已回座)"，无需人工
```

### 4.5 事件记录归档规范

| 层 | 位置 | 内容 | 保留策略 |
| --- | --- | --- | --- |
| 监测端本地 | `seat_monitor/events.json` | 事件全量字段 + 快照引用 | 主系统不可用时兜底，恢复后人工核对 |
| 主系统库表 | `events` + `work_orders` | 事件编号 EVT-*、座位、级别、状态、闭环人 | 长期留存，一事一档 |
| 证据快照 | `seat_monitor/snapshots/` | 触发时刻标注帧 | 建议保留 90 天，逾期清理 |
| 归档文件 | `archive/workorders.jsonl` | campus_ai 运行时 JSONL 归档 | 按学期轮转 |
| 审计 | `audit_logs` | 工单闭环、阈值修改、处置动作 | 长期留存 |

### 4.6 落地经验（来自获奖方案与学长复盘）

1. **复用成熟闭环**：占座事件走与霸凌预警相同的"事件 → 工单 → 闭环 → 审计"链路，不另建处置体系，评审时强调"一套底座多场景复用"；
2. **集成令牌对接**：`X-Integration-Token` 校验（失败返回 403/40300），体现接口安全意识；
3. **演示稳定性**：视频文件源自动循环播放，断流指数退避重连（2s→30s），确保评审现场摄像头异常时演示不中断；
4. **降级链叙事**：检测器 pose→fallback→degraded 三级降级，与获奖方案"可插拔、可降级"的工程叙事一致。

## 5. 模块四：行为规范图像识别

> 工程实现：`campus_ai/behavior_service/`（dataset / train / inference / face_match / service），配置 `behavior` 节点。

### 5.1 违规行为数据集训练与标注标准

| 项 | 标准 |
| --- | --- |
| 目标类别 | `slippers`（穿拖鞋进入教学区域）、`breakfast`（携带早餐进入教学区域），可扩展 |
| 采集规模 | 每类 ≥ 2000 张有效样本，正/负样本比约 1:2 |
| 场景覆盖 | 教学楼入口早高峰/午间/傍晚三种光照；正面/侧面/背面；遮挡（人流、雨伞）；不同季节着装 |
| 采集规范 | 固定机位实拍 + 公开数据集补充；实拍样本须脱敏（人脸模糊）后入训练集 |
| 标注格式 | YOLO 格式（class x_center y_center w h，归一化），逐图标注目标框 + 场景属性（光照/遮挡标志） |
| 标注质检 | 双人标注 + 第三人仲裁，框 IoU 一致性 ≥ 0.9 方可入库；10% 抽样复核 |
| 数据增强 | 随机翻转/缩放/色彩抖动/Mosaic；增强后样本不参与验证集 |
| 划分 | 训练:验证:测试 = 7:2:1，按场景分层抽样，防同场景泄漏 |

### 5.2 模型精度指标

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| mAP@0.5 | ≥ 0.80 | 两类别综合 |
| 单类召回 | ≥ 0.85 | 宁可误报转人工，不可漏报（与占座模块同一原则） |
| 误检率 | ≤ 5%（正常着装/空手负样本） | 控制学工复核压力 |
| 推理速度 | ≥ 15 fps（1080p，边缘 GPU）/ ≥ 5 fps（CPU 降采 960） | 满足入口实时监测 |
| 检出阈值 | `conf_threshold = 0.5`（现行配置） | 低于阈值直接丢弃，不入判定 |

### 5.3 违规行为识别判定规则

1. 检测置信度 ≥ 0.5 且目标框中心位于教学区入口 ROI 内，才进入违规判定；
2. 同一目标连续 3 帧检出同一类别才确认违规（抗单帧误检）；
3. 同一学生同一违规类型 60 s 去重（复用全局去重口径）；
4. 违规事件统一为蓝色级别（提示类），不触发语音震慑，避免教学区干扰；
5. 检出 → 人脸匹配 → 事件生成的全链路任一环节失败均不丢弃事件，降级为"身份待确认"转人工复核。

### 5.4 与学校人脸识别系统的对接接口规范

#### 5.4.1 接口契约

```text
GET {face_match_url}/api/face/match?face_ref={face_ref}
Header: X-Integration-Token: <与 config 一致>
超时: 3 s，失败按未匹配处理

响应 200:
{
  "code": 0,
  "data": {
    "student_id": "2023001",
    "name": "张三",
    "major": "软件技术",
    "class_name": "软件2301",
    "score": 0.93
  }
}
未匹配: {"code": 0, "data": {}} → 标记 needs_review
```

#### 5.4.2 对接约束

| 约束 | 规范 |
| --- | --- |
| 匹配阈值 | 相似度 score ≥ 0.85 认定同一学生，0.7–0.85 转人工复核，< 0.7 未匹配 |
| 降级 | `face_match_url` 为空或超时 → 本地模拟库匹配（演示）/ needs_review（生产） |
| 隐私 | 人脸特征仅用于事件定位，不存储原始人脸图；viewer 角色不可见身份字段 |
| 审计 | 每次匹配调用记录（时间、结果、耗时）入审计日志 |

### 5.5 学生身份信息匹配同步流程

```text
每日 02:00 全量同步：学校人脸库 → 本地学生信息缓存（student_id/姓名/专业/班级，不含人脸特征）
日间增量：学籍变更接口推送 → 即时更新缓存
匹配时序：违规检出 → face_ref → 人脸系统比对 → student_id → 本地缓存补全专业/班级
缓存策略：本地仅缓存非敏感学籍字段，特征比对永远走学校系统（单一权威源）
故障策略：同步失败沿用上一日缓存，事件标注"学籍信息可能滞后"
```

### 5.6 Agent 智能体推送内容格式与通知机制

违规事件经 `AgentService.dispatch_event` 统一推送，推送报文：

| 字段 | 内容 |
| --- | --- |
| `event_id` | EVT-YYYYMMDD-xxxxxxxx |
| `event_type` | violation |
| `severity` | blue |
| `summary` | "违规记录：软件技术软件2301 张三 穿拖鞋进入教学区域"（未识别为"身份待确认"） |
| `detail` | 违规类型中英文、置信度、学生信息、identified/needs_review 标志 |
| `targets` | 学工处（discipline_office）、班主任（head_teacher） |
| `location` / `source` | 教学楼A栋入口 / teach-cam-01 |

通知机制：站内推送即时可见；外部 Webhook 重试 3 次（`push.max_retry`）；未识别事件在学工复核队列置顶，复核确认身份后补录并更新事件，全程审计留痕。
